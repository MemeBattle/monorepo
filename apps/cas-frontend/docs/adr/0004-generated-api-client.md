# 4. The API client is generated

## Status

Accepted (2026-10-04), with [#776](https://github.com/MemeBattle/monorepo/issues/776).
Supersedes ADR 0001 (g). Builds on apps/cas ADR 0016 (the OpenAPI
description, #752).

## Context

ADR 0001 (g) kept the request and response types hand-written until CAS
published an OpenAPI description. It does now: `apps/cas/openapi.json`,
generated by utoipa, committed and drift-checked on the backend side. Every
operation has a descriptive id, and every error response lists the codes it
can carry as an enum.

Hand-written types next to each call drift from the backend without anyone
noticing, and the codes a screen branches on were strings nothing checked: a
`case` on a code the operation never answers compiled and was dead.

What was open:

- Whether to generate the types only, or the functions that call the API too.
- Which generator.
- Which part of the description the SPA needs.
- Who owns the transport.
- How the error codes reach a screen as types.
- Where the generic WebAuthn payloads get their shape.

## Decision

**(a) The types and the API functions are generated, and the output is
committed.** kubb reads `apps/cas/openapi.json` and writes one type module per
operation and one function per operation into `src/shared/api/generated/`.
The output is in the repository so a review shows what a description change
does to the client, and the build and the type check need no generator step.
The `api-client` CI job regenerates it and fails on any difference, so a
description change cannot merge without the regeneration. Generation is
deterministic, which is what makes that check possible.

**(b) The generator is kubb (`@kubb/plugin-ts` + `@kubb/plugin-client`).** It
was run against the real description next to the alternatives, and it is the
one that has a types-only mode, generates functions that call a client module
we own instead of a bundled transport, filters by path, and runs next to
TypeScript 7. What ruled the others out:

- `@hey-api/openapi-ts` bundles its own fetch client; its custom-client API is
  unstable, and its stable release does not run next to TypeScript 7.
- `orval` has no types-only mode and no path filter.
- `openapi-typescript` is dormant and does not run on TypeScript 6 or 7.

**(c) Only the operations under `/api/` are generated.** The OIDC protocol
endpoints (`/oidc/*`, `/.well-known/*`) are navigations of the browser and
requests of CAS's client applications; the SPA never calls them, and a
generated function for them would invite it to.

**(d) The transport is ours: `shared/api/client.ts`, the only caller of
`fetch`.** Every generated function calls `client()` from that module, which
keeps the behaviour the hand-written wrapper had: relative paths, no base URL
and no `credentials` option (ADR 0001 (f)), a JSON body, `ApiError` with the
stable code, `unknown` for a body that cannot be read, `undefined` for a 204.
kubb's example client builds `new URL(baseURL + url)`, which throws on the
relative paths the same-origin rule requires, so the module is written here
rather than copied. Any later interceptor (logging, retries) lives there and
nowhere else.

**(e) The models are types only.** `pluginTs` emits enums as inline literal
unions, so `generated/models/` has no runtime exports; the operation
functions are the only runtime code the generator contributes.

**(f) Error codes are types.** `ErrorCodeOf<Responses>` is the union of the
codes an operation's error responses declare. An entity exports that union
for each function whose failures a screen tells apart (`AddPasskeyErrorCode`,
the union over both requests of a ceremony), and a screen narrows with
`isApiError<AddPasskeyErrorCode>(error)`: a comparison or a `case` on a code
the operation never answers fails `pnpm ts-check`. `unknown` is always in the
narrowed union, since any call can end with an unreadable body. The mapping
from a code to what the screen says stays next to the screen; nothing about
errors moves into a shared module.

**(g) The `kubb` meta package is a dependency.** The plugins import
`kubb/config`, `kubb/kit` and `kubb/jsx` at runtime, so the leaner setup of
`@kubb/cli` with an adapter does not run. The meta package brings kubb's
studio and MCP tooling along as dependencies; they are dev dependencies that
never reach the bundle, and `generate:api` runs with
`KUBB_DISABLE_TELEMETRY=1`, since kubb's telemetry is on by default.

**(h) Entities keep the domain names and narrow the WebAuthn payloads.**
`Passkey`, `Me`, `Registered` and `SignedIn` are aliases of the generated
models, and the entity functions keep their signatures, so pages and specs do
not depend on the generator's names. The description leaves the WebAuthn
options and answers as `object`; the entity narrows the options with the
`@simplewebauthn/browser` types it already hands to the authenticator, in one
cast where the response is read.

## Consequences

- After a change to `apps/cas/openapi.json`, `pnpm generate:api` in
  `apps/cas-frontend` and a commit of the output; `docs/TESTS.md` says how.
- The generated directory is excluded from oxlint and oxfmt and is never
  edited by hand.
- A code a screen branches on that the backend stops declaring breaks the
  type check at the screen, which is the point.
- `@kubb/plugin-ts` depends on TypeScript 6, so a second TypeScript sits in
  the lockfile for the generator; the app still compiles with the catalog's
  TypeScript 7.
- The kubb releases this was built with were younger than the repository's
  `minimumReleaseAge` when it landed; they are listed by exact version in
  `minimumReleaseAgeExclude` until they clear it.
- Generated MSW handlers and zod schemas are not part of this; #739 mocks the
  network as designed.
